# 魔島大富翁（emoney）解析記錄

## 重建與驗證

完整重建入口為 `python tools/rebuild_emoney.py`，需要 Pillow。只拆容器可執行不需外部套件的 `python tools/unpack_emoney.py`。原始目錄 `local/binary/emoney/` 僅讀取；解包、原樣副本與驗證輸出到 `local/extracted/emoney/`，網站資料與圖片輸出到 `assets/games/emoney/`。

本機已使用 Codex 內附 Python 3 與 Pillow 12.3.0 完成重建。也可依序執行 `extract_emoney.py`、`export_emoney.py`、`verify_emoney.py`。網站建置為 `npm run build`。

`inventory.json` 記錄全部 95 個原始檔案的大小與 SHA-256。各版本 `manifest.json` 保存資源索引、位址、長度及 SHA-256。解包後從磁碟重新讀取索引及全部段，串接後與原資料包逐位元組比較；三份資料包均通過。這是容器拆分驗證，不代表各資源已解碼或規則已還原。

## 已確認：MONEY.DDT

- 檔頭為 little-endian uint32 索引筆數，本批三份均為 674。
- 每筆 16 bytes：12 bytes 名稱欄，加上 uint32 絕對位址。
- 名稱在第一個 NUL 結束；後方可能有殘留字元及非 ASCII bytes，不能將整個名稱欄解碼或視為補零。
- 第一段位於 `4 + 674 × 16 = 10788`。
- 最後一筆名稱為 `---.---`，位址等於 EOF（30674477），是結尾標記；有效資源為 673 筆。
- 每段結尾是下一筆位址。索引單調不減，允許空段；第 227 筆 `HUMAN.DAT` 為空。
- MAP01–MAP04 的 CMP 與 DAT 各有兩筆同名資源。輸出使用四位索引前綴，不能只按名稱寫出。
- 副檔名統計：CMP 368、ANJ 120、WAV 79、DAT 42、XMI 20；ICO/TYP 各 6；FNT/CDT/CHG/CHR/DLL/MAP/MAT/PCX 各 4。

## 已確認：版本差異

三份 DDT 的索引名稱、位址及長度一致，內容不同。以根目錄版本為比較基準：

- `完整修訂版`：12 段不同，為四張地圖的 CHR 與兩筆同名 DAT；索引 380、383、384、393、396、397、406、409、410、419、422、423。
- `舊版檔案`：5 段不同，為 ATTYPE.DAT（17）及四張地圖的 CHR（380、393、406、419）。
- 詳細雜湊及比較保存在本機 `version_comparison.json` 和各版本清單。目錄名稱只作版本識別，不據此宣稱版本優劣或修改效果。

## 已確認：文字

初步拆包找到 24 筆文字候選；完整解析先移除單一尾端 DOS EOF（0x1a），每版本可嚴格 CP950 解碼的完整文字資源增為 33 筆，另存 UTF-8。包含 CARD.DAT、C-INFO.DAT、MISS01–04/11–14/21–24、CITY-1–4、ARMY、LEVEL、EXTRA、FIGHT、TYPE 與地圖文字資源。

此篩選刻意保守，不代表其他 DAT 沒有文字。文字中的效果說明尚未和執行程式核對，不能直接當成已確認的運算公式。說明.txt 不能直接假設為 CP950；本輪未將其當遊戲規則依據。

## 已確認：圖片壓縮與圖像索引

以下指令依根目錄 MONEY.EXE 的檔案位址 `0x2e07e–0x2e0fc` 確認。這些位址是檔案偏移，不是 LE 邏輯位址。反組譯保存在本機 `analysis/money.dis`。

- CMP 首四 bytes 為 little-endian uint16 寬、高，後續為逐列指令。
- `0 n`：透明略過 n pixels；`1 n c`：重複顏色 c 共 n pixels；`2 n`：原樣 n bytes。
- `3 n`、`4 n`、`5 n`、`6 n` 分別原樣複製 4n、4n+1、4n+2、4n+3 bytes。不能把 3–6 都當成同一種 literal。
- `255` 為換列。解碼器要求每列寬度完全消耗，列數符合高度，不接受未記錄的指令與尾端 bytes。
- 368 個 CMP 全部解碼；其中 26 張尾端恰有 768 bytes 的 VGA 6-bit 調色盤。其餘使用 PAL1.TAB 的 6-bit 調色盤，轉 RGB 時乘 4。PAL1 和 MAP01.PCX 調色盤除第一個黑色項目外，縮至 DAC 值後一致（765/768 bytes 一致）；透明區另存 alpha，不把黑色直接當透明。
- ICO/TYP 是一組資源。TYP 每筆 `<II` 為長度、相對 ICO 的位址，連續覆蓋 ICO 全部內容。ITEM 是 80 張 48×48；MAND1 是 48 張 64×100；四張地圖分別為 168、214、174、155 張 64×80，共 839 張。
- 地圖圖塊同時有 RLE 與原樣像素。程式 `0x303e9`、`0x3044a` 以長度 0x1400（64×80）分流，短於此值走 RLE，否則走原樣複製。本批原樣段均恰好 5120 bytes。
- PCX 與外部 PIC 是標準 PCX，可用 Pillow 解碼；副檔名不能作唯一辨識依據。外部 SETUPU.CMP 也已解出 25×25 圖片。

## 已確認：ANJ

- 檔頭 `<II` 為幀數、最大段長欄位；後續每幀 `<6I` 為 x、y、寬、高、壓縮長度、檔內位址。索引長度為 8+24×幀數。
- 各幀使用同一個 RLE 指令集，不附 CMP 的寬高頭。每段輸入與解碼長度皆完整核對。
- 資料包 120 組動畫共有 3300 個索引幀；其中 30 幀是 (640,480,0,0)、長度 16 的畫面外空矩形，保留其原始 payload 及索引，不把殘留 bytes 假裝解成像素。
- TK19.ANJ 為合法零幀檔，只有 8-byte 零檔頭。
- 外部 SHOW.ANJ 另有 260 幀，全部解碼。輸出為逐幀 PNG 和座標清單；尚未還原遊戲播放時序，不擅自製成指定幀率影片。
- SHA-256 去重後，資料包動畫共有 3124 個索引幀；這個數字不能誤報成原索引總數 3300。

## 已確認：地圖與資料表

- MAP/MAT 均為 8208 bytes：`<II` 寬高、4096 個 uint16 格子（固定 stride 64）、8 bytes 尾端資料。尾端完整保留，未猜填用途。
- MAP 對應地圖 ICO 圖塊；一格 64×80。四章已按格子完整重組，並和同章 CMP 縮圖核對道路、城鎮及山脈、水域配置。縮圖一格為 8×10。網站同時可切換全圖與原遊戲縮圖。
- CHG 為 uint32 圖塊變更清單，保留全部值；MAT 格子語義尚未完整追蹤。
- ITEM.DAT 每筆 42 bytes，共 106 筆（包含「無」），另有 1 byte 尾端。程式 `0x3b0d7` 除以 42 取得筆數。欄位：+0 ID、+4 名稱（12 bytes）、+16 種類、+17 裝備許可遮罩、+18 攻擊、+22 命中、+26 防禦、+30 迴避、+34 價格、+38 額外欄位。裝備比較見 `0x3847b–0x386af`，不將所有欄位稱為加成（武器命中是命中值）。
- 第57槽也是空名稱/ID0，不可當作一項具名物品；網站共有104項具名物品，裝備48項、卡片43項、其他13項。裝備種類為1–6，11–13是消耗/交涉物品，50以上可為卡片，不能用「種類不為0」判斷裝備。CARD001–004是圖案卡面，不是前四把劍；卡片圖片只按已存在的 CARD058–100 對應，其他物品圖像關聯未確認前不套用。程式格式字串 card%03d.cmp 位於0x8188e。
- 卡片效果文字來自內附 CARD.DAT，尚未逐卡核對執行分支，公開欄位明示效果待確認；例如腐朽卡的內附說明寫毀城牆，但程式顯示文字寫物品減半，差異不得隱藏。
- MONSTER.DAT 每筆 170 bytes，共 33 筆（包含 NONE），另有 1 byte 尾端。程式 `0x3b11b` 除以 170；+4 名稱、+18 圖像代號、+30 等級、+38 體力上限、+42 體力成長、+50 精力上限、+54 精力成長、+58 攻擊、+62 攻擊成長、+66 防禦、+70 防禦成長、+74 智慧、+78 智慧成長、+82 運氣、+106 命中、+110 迴避、+114/118/122 技能。招募成長計算見 `0x32232–0x32288`，使用基礎值加 `(等級−1)×成長`。
- 網站兵種圖依記錄的圖像代號選取同名 CMP；程式也從 +18 格式化 `%s.cmp`。不按名稱猜圖。
- 主要技能表是 SPELL2.DAT，每筆 21 bytes，72 筆中有 69 個非空名稱。+0 ID、+4 名稱12 bytes、+16 屬性、+17 目標、+18 範圍、+19 動畫、+20 精力消耗。程式 `0x3b14a` 明確載入 spell2.dat；`0x37bbd–0x37be8` 按 21-byte 索引讀出名稱與 +20，`0x37c6c–0x37c89` 比較精力是否足夠。
- SPELL.DAT 為另一份 20-byte 結構（另有 1 byte 尾端），不等同實際載入的 21-byte 表。例如主動表「轉移」耗魔20，EXTRA.DAT 文字寫12；網站採用實際載入表。
- 四章 CHR 每份 1532 bytes，即四筆 383-byte 主角。名稱 +4（10 bytes）；等級 +23；體力基礎 +31、成長 +35；精力 +43/+47；力量 +51/+55；敏捷 +59/+63；智慧 +67/+71；運氣 +75；金錢 +191；四個隨從 ID +255、等級 +271。技能槽 +131，習得等級 +141，實際 SPELL2 ID 為槽值+50（程式 `0x37c21–0x37c64`）。
- 主角肖像依人物順序+1選 FACE%02d00.CMP；程式 `0x1c2da–0x1c2eb` 可核對。四章初始等級為1、10、20、30，能力欄位仍是相同基礎值，不能標成各章成長後能力。
- 各章 DAT 每筆 170 bytes：+0 ID、+4 名稱12 bytes、+16/+20 座標、+24 等級、+28 金額、+40 類型、+44/+45 城牆/河、+50 五個守軍 ID、+70 五個守軍等級。CITY-n 文字表和實際二進位座標有差異，網站採用實際地圖 DAT。金額的完整買價/稅收語義尚未追完，網站明示用途待確認。
- ATTYPE.DAT 每筆63 bytes，113筆另加1 byte尾端；GROUP.DAT 每筆52 bytes，11筆另加1 byte；ITEMLOC.DAT 為48組 int32 座標；TRANTAB.DAT 為256色查表。完整解析輸出及未分配欄位僅留本機。
- 所有記錄解析都另保存完整原始 bytes，不能丟掉看似多出的 1-byte 尾端，也不能假設它是固定零。

## 已確認：字型、音樂與程式

- 字型依原樣位元輸出圖集：GAMEASC/2 每字8×15（15 bytes）、FONT16/GR16 每字16×15（30 bytes）、24字型每字24×24（72 bytes）。本批41,349個去重字形已從圖集逐字裁回並編碼，與原始 bytes 一致。字符索引到 Big5 的完整映射仍待確認，圖集不冒稱完成文字辨識。
- 79 個 WAV 均由標準 RIFF/WAVE PCM 解析，讀取樣本數、取樣率、聲道及位寬，核對實際 PCM 長度。
- 20 個 XMI 均解析 IFF 容器及 EVNT 事件，匯出標準 MIDI；note-on 的時長轉成 note-off。EVNT 結束事件後，本批允許零或一個零補齊 byte，不忽略任意尾端資料。MIDI 沒有合成遊戲原本音色；原 XMI/TIMB 等區塊仍保留。
- MONEY.EXE 是 DOS MZ+LE。LE 頭位於0x2a50，物件表/頁表依標頭讀取，頁號為三 bytes big-endian，頁大小4096；6份版本均分別拆出3個物件，不執行或修改原程式。
- 根目錄程式初始化資料段中的中文 NUL 字串嚴格 CP950 解出後另保存偏移證據。網站只使用154段不需要 printf 執行期代換的具名文字與對話；單一漢字可能出自數字資料，不直接公開成對話。

## 完成範圍與仍待確認事項

完整解包涵蓋三份資料包的所有673個資源槽位，包括空資源、全部圖片/動畫、ICO/TYP、聲音、音樂事件、文字、字型及結構化資料表；外部圖片、開場動畫、字型和程式物件也有輸出。95個原始檔均另存原樣副本並核對雜湊，音效驅動程式和系統執行檔視為執行環境元件保留，不當作遊戲圖像解碼。

以下是語義/執行行為的限制，不應聲稱已完全還原所有規則：

- 尚未追完全部戰鬥、卡片與經濟公式，部分內附說明和實際程式有差異。
- MAT、部分 ATTYPE/GROUP 欄位、字型字符對應及動畫播放時序尚未完整確認。
- 同名索引在執行時的選取策略及各修訂版修改效果仍待逐一路徑核對；各版本已獨立完整拆解。
- IMAGE.IDX/DAT 與 SAV 是隨附使用者狀態，已原樣保留及逐byte/uint32匯出；完整語義尚未確認，不用它們覆蓋遊戲原始設定。
- 網站沒有顯示未分配欄位、原檔路徑、位址、十六進位或解包過程；公開資料可獨立由 assets 載入，不依賴 local。

驗證入口 `verify_emoney.py`，機器結果在 `validation/data_checks.json`；瀏覽器操作與畫面記錄保存在同一個本機目錄。
