# TOCO 資料格式紀錄

執行 `python tools/extract_toco_data.py`，輸出至 `local/extracted/TOCO/data/`。
原始檔案不會修改。`overview.txt` 可直接閱讀，`stages.csv` 可用試算表開啟。

## 已驗證的檔案結構

以下結構符合目前全部 31 個 GAME*.DAT（30 個編號關卡及 GAME12A）。
整數為 little endian；文字為 CP950，以 NUL 結束。

| DAT 位移 | 結構 |
| --- | --- |
| 0–19 | 地圖素材名稱 |
| 20–39 | 人物圖像檔名 |
| 40–59 | 音樂檔名 |
| 60–79 | 關卡名稱 |
| 80–81 | 兩個地圖分塊維度值 |
| 82 | 配置紀錄數量 |
| 83 | 未知旗標 |
| 84 起 | 維度值乘積 × 520 筆，每筆 5 bytes 的地圖資料 |
| 地圖資料後 | 配置紀錄，每筆 13 bytes |

地圖每筆 5 bytes 暫以兩個 u16 與一個 u8 匯出；尚未確認地形、圖塊及排列規則。
配置每筆前兩個 bytes 語意未知，接著是四個 u16，最後一個 u8 與一個 u16。
四個 u16 在全部 705 筆中都呈現兩組相同的值，很可能是兩組位置座標；
尚未以遊戲執行結果確認，故輸出為 coordinate_words，其他欄位也不假定是敵我、兵種或等級。
每筆保留位移與完整原始十六進位值，方便後續對照。

STG：u16 紀錄數 + 每筆 100 bytes 的文字。
MSG／END：u16 紀錄數 + 每筆 106 bytes；前 6 bytes 為三個未知 u16，其餘 100 bytes 為文字。
所有讀入檔案均驗證完整長度，CP950 以嚴格模式解碼。

## 兵種與敵人

EXE 中找到七系兵種名稱的連續表，共 42 個槽位，其中 31 個為名稱、11 個為 XXXX 預留名稱。
保留原始表索引與 EXE 位移。尚未確認表索引與地圖配置或圖像 ID 的對應。
進一步解析已確認兵種模板、轉職與技能，詳見下節。敵人名稱、AI、勝敗條件與 WAR 儲存資料仍未解碼。

先前圖像解包已涵蓋 GROUP 下的 FTEAM、FAGST、FMAST 圖集；
這些檔名前綴的角色分類與兵種名稱對應尚未確認，無內嵌調色盤者仍採 EGA 暫代配色。

## 兵種詳細資料（新增）

執行 `python tools/extract_toco_units.py`，產生網站的 `unit-details.json`、
`skills.json`、`enemies.json` 與單格兵種／敵人 PNG。下列位移為目前 EXE 的檔案位移；
解析器檢查關鍵機器碼，避免套用至不相容版本。

- DS 對應檔案基底 0x2f3a0；0x1b7b0 的程式將 DS:0x1692 起每筆 40 bytes 的模板複製出來。
- 友軍模板位於 0x30a32，共 31 筆；每筆 byte 0 是系內職業索引、byte 4 是職業系索引。
  每系六槽的名稱表須移除 XXXX 預留槽後，才對應此連續模板表。
- 模板 +13 為生命 u16、+17 為技法 u16；+21 攻擊、+22 防禦、+23 反應、+24 智慧。
  +28 到 +39 為十二個技能槽，0 代表空；技能表位於 0x2fc46，每筆 30 bytes，前 20 bytes 是名稱。
- 0x31c16 起為 31 筆轉職表，每筆兩個一基底職業 ID，0 代表無分支。
  0x24d65–0x24ebd 的程式確認分支讀取及新職業索引換算。
- 0x31c54 起是每職業六個轉職係數。0x24ede–0x25026 確認生命／技法係數乘 25 加 15；
  攻擊係數乘 3 加 5；反應係數乘 3 加 2。防禦與智慧在此轉職流程沿用清零的加成槽，故為 0。
- 0x24abb–0x24af6 確認普通升級生命／技法 +7–10，防禦／智慧 +1–2，攻擊 +2–3，反應 +0。
  隨機函式 0x288ca–0x28916 使用含上下限的區間。轉職流程取代該次一般升級流程，不將兩者相加。
- 生命／技法上限 999，其他四項上限 255。模板值並非角色當前屬性，亦不代表全角色的初始值。
- 0x1ec4f–0x1ec69 以 DS:0x1b42 加敵方一基底 ID ×40 複製模板；敵方 1 對應 0x30f0a。
  網頁收錄有 FAGST 圖像的 33 個編號；尚未處理特殊首領模板。難度會影響實戰數值。
- 戰鬥圖像使用 FTEAM1–31 與 FAGST1–33 的第七格。其調色盤未內嵌，網頁明示使用 WOMAN.PIC
  內嵌調色盤暫代，不宣稱為已驗證戰鬥配色。

### 技能數值

每筆 30 bytes：+20 效果類型（0 傷害、3 治療、4 痲痺、5 石化），+21 範圍旗標；
+22 耗魔 u16，+24 基礎威力 u16，+26 施放距離 u16，+28 影響範圍值 u16。
0x103b8–0x103cf、0x124c8–0x124dd 以 +22 和當前技法比較。
0x12520–0x12567 對傷害／治療的 +24 基值加入施術者智慧的一半，後續還有戰鬥計算，
因此網站標示為「傷害基值／治療基值」，不當成最終扣血／補血。
狀態技能顯示效果值，不冒稱傷害。+26 在 0xb51c 加一後用於選取射程；
+28 在 0x124fc 傳入 0x14c13 範圍標記函式，1 為單體，其餘以目標為中心延伸值減一格。

### 敵人名稱與公式頁

目前未在 EXE、GAME.LNK 或關卡資料找到可對應 33 個敵方圖像的官方名稱表。
`assets/games/toco/data/enemy-names.json` 的名稱是依圖像外觀編寫的暫名，
`status=descriptive_unverified`，不屬於解包得到的原文。網頁敵人區與技能使用者區均標明暫名。

移動：0x19200–0x19238 從單位 +23 取移動點，傳給 0x168ae；
0x16571–0x1659e 逐格扣除地形成本。0x15925–0x15a30 依職業通行旗標、
地圖類型及飛行系選取成本表 DS:0xfdc／0x1010，不可通行標記為 99。
這也確認 +23 同時在升級文字稱「反應」、狀態畫面稱「移動」，不是另有一個已確認的反應屬性。

治療：0x1280a–0x12825 算基值 + floor(智慧/2)，0x128c3–0x12990 套用缺血上限。
法術：0x12520–0x12543 以同樣加智慧方式將威力傳給 0xd1f5 傷害例程。
攻擊：0xbe01–0xbe0d 傳入兩個單位攻擊值，亦使用該傷害例程。
0xd33c–0xd375、0xd4f6–0xd52f 可見先手差值過低時的 15–25／10–15 隨機替代；
0xd43f–0xd478、0xd5f9–0xd632 為反擊的 10–15／5–10。
0xd391–0xd3bc 及 0xd54b–0xd576 檢查職業、狀態、技能與致死條件。
0x15d94–0x16074 建立包圍／支援／地形修正。浮點模擬中斷與出手方向分支仍待實戰核對，
所以公式頁只公開已確認的移動／治療式，以及攻擊／法術的部分流程，不宣稱完整精確傷害公式。

### 初始部署範圍（更正）

魔法陣的地形種類 9 不是初始部署區域；先前的魔法陣單點標示已移除。
每筆 5 bytes 地圖資料中，第二個 u16 的 bits 8–11（即 byte +3 的低四位）
為獨立範圍旗標，目前原始資料為 0 或 1。0xa3d2–0xa476 在初始化時檢查此旗標，
將視角定位到標記區域並清除其遮蔽位元；區域與敵方配置索引、地形種類均獨立。
網站依原始旗標逐一覆蓋 24×24 圖塊，不從魔法陣或守護地推算半徑。
30 個正式關卡與 GAME12A 均有標記；各關區域大小不同。

### 傷害分支細查

`tools/verify_toco_formulas.py` 核對原始 EXE 的七個關鍵簽章，不執行或修改遊戲。
以下是靜態反組譯結果，尚未以 DOS 執行時追蹤驗證暫存記憶體的實際內容。

DS:0x6a3/0x6a5/0x6a7 與 0x6a9/0x6ab/0x6ad 分別為兩組包圍、支援、地形修正。
每組 K=trunc((包圍+支援+trunc(地形/2))/80)，在整數除法後才轉成浮點。
浮點常數 DS:0x6ec 為 80.0，不是百分比 100。
0x4db0 的轉換函式將 x87 RC 設為 11，使用向零截斷，再回傳整數低位。

分支 0（DS:0x1224=0）在 0xd47b–0xd52f：P=A*(1+K1/80)，E=D0*(1+trunc(T0/80))。
比較原始 D0 與 P，不是 E 與 P。D0>=P 時取 10–15；否則轉整數 P-E，
將低 16 位存入無號傷害；小於 15 時改取 15–25。
若修正造成差值為負，不能自行以 max(0,差值) 修正，原式有低位轉換行為。

分支 1（非零）在 0xd2db–0xd375：P=A+U*K0，E=D1*(1+trunc(T1/80))。
P<=E 時取 10–15；否則轉整數 P-E，低位小於 15 時改取 15–25。
原始指令 0xd2e7 `CD 35 46 F4` 讀 [bp-12] 浮點，0xd2f2 才寫入該槽。
入口到該讀取點沒有對此槽初始化；兩個模板輸出緩衝區均不與此槽重疊。
因此 U 在靜態控制流中未定義，不能把它推測成 A 或 0，也不能據此保證特定實戰傷害。

反擊在 0xd3c1–0xd478／0xd57b–0xd632 使用 B*(1+K/80)/80，扣除另一方修正防禦。
正差截斷後低於 10 改取 10–15，非正差取 5–10。
職業、狀態、技能條件外，先手傷害與生命的比較使用 `jbe`，等於生命時仍可通過該判斷。
前文「先手致死即禁止」的簡化不精確，網站已改用實際比較條件。

法術將 A 設為基值+trunc(智慧/2)、B 設為 0，再呼叫相同例程。
這些結果釐清先前的倍率／取整待確認項目；U 的實際數值需要執行時記憶體，
不存在只以兵種屬性為輸入、能涵蓋此分支所有情況的單一純公式。

## 部署格與事件單位
部署旗標以 2×2 圖塊為一格，隔列向右偏移一個圖塊；不是逐圖塊的方格。export_toco_maps.py 驗證全部 31 張地圖的部署旗標均完整涵蓋於這些交錯格。
事件單位使用我方兵種表的索引，圖像及屬性顯示該兵種預設值；不將模板數值當成事件角色經劇情調整後的實際數值。


## 招募、指揮官與兵種點數
- DS:20e3（EXE 0x31483）初始 word 為 50。勝利旗標 DS:0ec9 成立時，0x27f82–0x27f9c 的結算加 5。
- 招募模板從 DS:157a（EXE 0x3091a）開始，7 筆 ×40 bytes；byte 27 是招募費用。0x1fd5a–0x1fd7f 先比較餘額，再扣除該 byte。費用依序 5、2、3、9、6、4、7。只有各系初階職業可直接招募。
- 遣散選項索引 10–16；0x1fe86–0x1fe98 用 DS:13ea + 選項×40 +27（即同一組 DS:157a 模板），返還該系初階招募費。升級經驗門檻為模板 word 11，不能當作費用。
- 主角初始模板 DS:0ed9（EXE 0x30279），與 DS:1552（0x308f2）相同；系別 7、初始生命 50、技法 15、攻擊 20、防禦 17、反應／移動 18、智慧 10，技能 25、26。戰鬥圖像專用 FROLE.GRP；0x20f61–0x20f74 設定主角識別 99。網站以 99 作為主角資料 ID，避免改動原有兵種 ID。
- 0x24ca3–0x24d65 的主角轉職選擇允許七系（鍵盤 1–7）；一般升級與其餘職業共用前段成長流程，轉職另受等級與劇情條件限制。
- 驗證片段保存在 local/extracted/TOCO/recruitment-evidence.txt，原始遊戲未修改。

## 地形耗點表
extract_toco_terrain.py 匯出野外與城內各 13 種地形，名稱依 EXE 內「土地」起連續 26 個字串。
0x15925–0x15a30：DS:0fdc 為野外、DS:1010 為城內，逐地形兩個 u16（地面、飛行），DS:1044 逐地形兩個通行遮罩（野外、城內）。系別 6 使用飛行耗點；其他系別使用地面。遮罩以 0x40 >> 系別，指揮官系別 7 特別使用 0x20。99 為不可通行。通行遮罩限制優先於耗點。
經驗：0x2507b–0x2517b 檢查行動者有效、非零傷害與存活，將傷害加入模板 word +9；致死時使用目標 word +15（扣血前生命）以封頂。word +11 為門檻，初階模板為80；0x25039 轉職時翻倍。0x25100 與更新後門檻比較，0x2513e 扣除的是更新後門檻，不能簡化為每次都扣舊門檻。治療等行動經驗尚未確認。
`n地形範例使用 DAT header +83 的野外／城內模式、圖塊旗標高四位地形類別，從相同類別的交錯 2×2 格選取最常見圖塊組合，直接按原 GRP 調色盤輸出。沒有完整 2×2 格時使用原單一圖塊；沒有對應地形時不補造圖像。
