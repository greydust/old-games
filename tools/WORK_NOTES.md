# 作業經驗與後續核對事項

記錄可供後續作業重用的知識、曾發生的錯誤與驗證方式。遊戲的位址、欄位與指令依據放在各遊戲解析文件；原始證據、暫存檔及畫面放在 `local/extracted/`，不納入 Git。新增結論時應附驗證方法；推論及未完成部分需明示。

## 2026-10-20：魔島大富翁初步解包

- 固定長度名稱欄不保證 NUL 後都是零；需先截斷再解碼。本次整欄 ASCII 解碼曾因結尾標記後的殘留 bytes 失敗。
- 具名容器可能包含重複檔名；輸出需保留索引編號，避免覆寫。版本比較也按索引比對，不能轉成以檔名為鍵的字典。
- 同大小、同索引的資料包不一定相同；應保存整檔及各段雜湊。各版本分開解包，再從輸出重建比對原檔。
- Windows 終端預設編碼可能無法列印中文路徑；本次 Python 輸出設定 `PYTHONIOENCODING=utf-8`。這與原始文字資源編碼是兩回事。
- 已確認格式及待確認項目見 [EMONEY_FORMAT.md](EMONEY_FORMAT.md)。
- RLE 的 literal 指令不一定都只有一種長度：本次 3–6 分別對應4n到4n+3。須由實際複製指令核對，不能只用幾張看似成功的圖片推論全部格式。
- 同一圖像索引內可能混用原樣像素與壓縮資料；本次地圖以5120-byte門檻分流，誤把原樣圖塊套進 RLE 曾出現 unknown opcode 129。
- 動畫空矩形可能仍有殘留 payload；零尺寸、零幀檔案和有效透明幀需分開記錄，不能為讓解碼通過而把殘留 bytes 當成有效像素。
- DOS EOF 0x1a 可能讓完整文字被誤判成二進位；只對確認的末尾符號處理，嚴格解碼並保留原檔。文字候選由24筆增加為33筆。
- 內附設計說明不等於執行期資料：本次 SPELL.DAT、EXTRA.DAT 和實際載入 SPELL2.DAT 有差異。須追蹤檔名、記錄步長及欄位讀取後再匯出。
- 字型圖集的完整性可用逐字裁回位元的 round-trip 核對；圖集完整與字符編碼映射完成是不同結論。
- 公開對話不能直接列印 printf 模板或從數值表誤解出的單字。完整證據留本機，網頁使用不需執行期代換的確認文字。
- 資料槽位數不等於具名項目數。本次物品表除第0槽外，第57槽也為空，修正後公開104項物品。類型值不為0也不等於裝備，卡片和消耗品同樣可能有非零類型；需用已追蹤的種類範圍或明確分類。
- 相似的圖檔命名不能直接跨類別對應。本次 CARD001–004 並非物品1–4的圖像；已移除錯誤關聯，未確認的裝備圖像保留空白，完整卡面仍存本機解包。

## 2026-10-20：高報酬戰將（HR）

本次詳細依據見 [HR_FORMAT.md](HR_FORMAT.md)，重建入口為 [extract_hr_data.py](extract_hr_data.py)，驗證入口為 [verify_hr.py](verify_hr.py)。

### 解包完整性與格式辨識

- 「所有檔案已列出」「容器每段已拆出」「每段已解碼」「遊戲規則已還原」是不同完成程度，報告進度時不能混用。本次已保存 148 個檔案並處理全部非空 MRG 段，但任務與戰鬥語義仍有未完成部分。
- 相似容器不能假設相同結尾規則。HR 的 MES 最後一個位址是結尾，MRG 的最後一個位址仍是段起點，必須延伸至 EOF；否則會漏掉 ESPMES 與 EXIST 的最後一段。
- 除了檢查段數，還要將拆出的段串接回去，與原檔有效資料區逐位元組比較。原樣副本的 SHA-256 也要核對。
- 對異常索引只允許已觀察、已記錄的特例。例如 COUNTRY.MES 結尾超出原檔 1 byte，不應把所有越界都當作可忽略。
- 「解壓成功」應要求輸入與輸出長度都精確消耗；圖片也需檢查尺寸、模式、遮罩與調色盤，不只確認 PNG 能開啟。
- Borland 覆蓋程式內的段編號不能直接當成原 MZ 段位址。反組譯的跨 64 KiB near call 也可能顯示回繞，須依覆蓋區及呼叫目標核對。

### 角色、兵種與圖像的關聯

- 不用名稱連接角色表和兵種表。翻譯名稱可能錯位、縮寫或拼法不一；應先追蹤遊戲實際使用的 ID、指標或間接索引。
- 本次先用中文名稱找兵種，導致鐵盧姆、露與迪詩蕾德的肖像及能力配錯。只修肖像索引不足以解決問題：隊伍記錄 +85 明確指定六位隊長的兵種 ID 為 0–5，能力也必須依此對應。
- 人物肖像和兵種戰鬥圖是不同資源。兵種 +21 不能直接拿來索引 FACE；程式以該值乘 3 讀取 BC32 的三幀組。網站人物頁使用已和 OP 介紹圖比對的肖像，兵種表使用已追蹤呼叫的戰鬥圖。
- 圖片存在、尺寸正確、沒有載入失敗，都不能證明它屬於該人物。驗證需同時涵蓋程式索引與可辨識的角色介紹圖。
- 編成內的類別也不一定就是兵種 ID。HR 的成員類別先索引該編成的候選兵種表，再取得實際兵種。
- 網頁採用正確角色名稱時，原表名稱差異仍需保存於本機證據，避免把網站的標準化名稱誤認為原始記錄。

### 公式與經濟資料的呈現

- 整數公式要保留每一步截斷、運算寬度及上限；不能先合併分數再取整。例如能力每 100 經驗乘 1.5，10 → 15 → 22 → 33，不等於最後才對 `10 × 1.5³` 取整。
- 公式旁提供數字例子，區分基本值、成長後能力、裝備加成與能力上限，避免使用者誤解。
- 基本價格、當地價格、買價、賣價與庫存是不同欄位。買賣方向應從扣款／加款流程確認，不能只看公式大小猜測。
- 本次 57 個市場只有 15 組不同價格倍率。切換市場後價格不變，可能是合法的同價市場，不能直接判定事件沒有觸發；需選倍率不同的市場驗證。
- 已驗證的例子：交易能力為 0 時，金屬針在拜亞蘭斯城買價為 816Ｇ，在夏雷吉市為 1,008Ｇ。網頁顯示目前市場、同價市場和當地倍率，讓價格變化可見。
- 初始庫存需明示為初始值，不能顯示成遊戲進行中的即時庫存。
- 道具資料欄位有數字，不代表使用流程一定讀取。本次復原藥與特殊膠囊的一般使用路徑不回復體力，仍扣使用次數；不能只依名稱或未使用欄位猜成疲勞回復。其他效果路徑與實機行為仍須核對。

### 任務及陣形

- 任務文字藏在一般事件對話裡時，解出全文仍不等於提供可查閱的任務資料。需另整理目標、報酬、條件與分支，保留原對話供核對。
- 對話存在不代表有可到達的觸發入口。本次熱浪有完整文字，但尚未確認實際入口，不能直接寫成已驗證可進行的支線。
- 對話與程式可能不一致。槍術大會對話寫報名至 6 日，已追蹤的報名分支只接受 3 月、9 月的 1–5 日；文件需同時保存兩者，不默默改原文。
- 只確認部分旗標時，不能宣稱完整攻略。本次已確認舞孃護送入口、寒流完成報酬與古代財寶支付分支，仍有其他條件未追完。
- 陣形不只是畫面裝飾。已追蹤的射擊選目標流程會使用橫向位置與隨機值計分；但這不足以證明整個遊戲沒有任何其他陣形加成。

### 網頁共用控制項與驗證

- 網站出現同類選單問題時，修共用行為，避免每個分頁各自修補。共用實作為 [select-menu.js](../assets/select-menu.js)。
- 本次瀏覽器的原生下拉選項反白寬度與選單不一致，改用整列選項呈現，同時保留原生 select 的值、input/change 事件與編輯器延遲載入選項。
- 自訂選項浮層要避開祖先表格的 overflow 裁切；本次將浮層放到 body，依控制項位置安排上下展開，並處理捲動、離開焦點、Esc 與頁面切換的關閉行為。
- 關閉浮層可能觸發 blur/focusout，再次呼叫關閉函式。關閉流程需要防重入；本次曾因移除同一節點兩次而中斷 change 事件，造成畫面選項變了、資料卻沒更新。
- 包裝原生 select 會改變 parentElement。原本依賴直接父元素的程式要一併核對；臥龍傳劇本控制區改以 `closest('.wd-controls')` 定位。
- 選單須驗證實際結果，不只檢查選中文字：戰車篩選應剩 8 筆、地圖圖片應切換、事件對話應為 1,024 筆、劇本與關卡內容應跟著更新。
- 同時核對鍵盤方向鍵、Enter、Esc、選項整列反白、停用狀態及長清單捲動。編輯器的資料載入後選單尚未在本次以載入遊戲檔的方式完整實測，不把共用程式涵蓋視為已做過全部編輯器測試。
- 排序依欄位型別處理：數字按數值、文字以 zh-Hant collator 比較；同值保留穩定順序、空值放最後。搜尋及篩選後保留排序，並用 aria-sort 表達方向。
- 建置、語法檢查及資料驗證通過，仍不代表視覺與對應關係正確；需要瀏覽器操作及畫面核對。證據放在 `local/extracted/hr/validation/`。
